# Audit Target: Insecure Configuration

This is a small Spring Boot billing service generated by an AI assistant. It
builds and boots cleanly. Your job is to decide whether it is *safe to deploy* —
because a configuration that starts can still ship with its front door open.

## What is here

- `pom.xml` — Spring Boot web / security / data-jpa / actuator app.
- `src/main/resources/application.yml` — the application, datasource, gateway,
  logging, and actuator configuration.
- `src/main/java/com/acme/billing/` — the security, CORS, and gateway-client
  wiring that reads from the configuration.

## Your task

Audit the configuration set and produce a **findings list**. Run a deliberate
pass over every file and key — do not stop at the first thing that looks wrong.
For each defect you find, record:

- **Location** — the file and the exact key (or the class and line).
- **Flaw class** — insecure default, exposed secret, overly permissive setting,
  environment/framework error, or configuration hallucination (a key that looks
  like hardening but the framework silently ignores).
- **Risk** — the concrete exploit or exposure it permits (who reaches it and
  what they gain), not just that it "looks risky."
- **Recommended fix** — correct-in-place for a bad setting, or remove-and-relocate
  for data that should never live in the file.

Pay deliberate attention to any key that *looks* like a security control —
verify each against the framework's real property list before you trust it.

There is no answer key in this folder. Produce your findings on your own.
