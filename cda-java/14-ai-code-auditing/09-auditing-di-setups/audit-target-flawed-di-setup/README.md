# Audit Target: Flawed DI Setup

This is a small Spring orders service generated by an AI assistant. It compiles
and passes a single-user smoke test. Your job is to run the **systematic
DI-audit pass** over its wiring and produce a findings list — because the
defects here are the quiet ones that a casual read slides past.

## What is here

- `pom.xml` — minimal Spring Boot web app.
- `src/main/resources/application.yml` — application config.
- `src/main/java/com/acme/orders/` — the controllers, services, repository,
  pricing strategy and its factory config, and the per-request/per-cart state
  holders.

## Your task

Do **not** jump to the first thing that looks wrong. Run the four-step pass in
order and record every finding as you go.

1. **Enumerate** every binding the container wires — each `@Component`,
   `@Service`, `@Repository`, `@RestController`, and each `@Bean`. This
   inventory is your worksheet.
2. **Trace provenance** for each binding: where does the implementation come
   from? Flag any whose target is decided by untrusted config, environment,
   request data, or dynamic resolution — and name who controls that input.
3. **Check scope** for each: does the bean's lifetime match the state it
   carries? Flag any stateful singleton and name the state it shares.
4. **Verify boundaries** for each consumer: list not what it *uses* but what its
   injected dependencies *can reach*, and compare against what its role
   warrants. Flag any over-broad or high-trust dependency, and name the boundary
   that should exist.

For every finding record: **location** (class and binding), **defect class**
(untrusted injection, scope/lifecycle defect, over-broad wiring, or missing
access boundary), the concrete **risk** (the exploit, with who reaches it), and
a **recommended fix**. Note which pass step surfaced each finding.

There is no answer key in this folder. Produce your findings on your own.
