# Audit Target: Dependency Injection Graph

This is a small Spring reporting service generated by an AI assistant. It wires
together a handful of beans through dependency injection. Your job is **not** to
fix anything yet — it is to *map* the wiring and flag what looks suspect.

## What is here

- `pom.xml` — minimal Spring Boot web app.
- `src/main/resources/application.yml` — application config.
- `src/main/java/com/acme/reporting/` — the controller, service, request
  context, exporter interface and implementations, audit-log interface and
  implementation, and the `@Configuration` that wires them.

## Your task

Draw the **dependency graph** of this setup and annotate it.

1. **Enumerate the bindings.** List every bean the container manages — every
   `@Component`, `@Service`, `@RestController`, and every `@Bean` method.
2. **Draw edges.** One node per bean; an arrow from A to B when A injects B.
3. **Annotate each node with the three moving parts:**
   - **What** concrete implementation is wired (especially where an interface is
     involved — is it the obvious intended one?).
   - **What scope** it has (singleton? request? prototype?) and whether it holds
     state that must not be shared.
   - **From where** it is provided (a fixed binding in code, or chosen from
     config / the environment / a request at runtime?).
4. **Circle the suspect nodes.** Flag any node where one of the three answers
   looks wrong — a singleton that seems to hold per-user state, a binding whose
   target is decided at runtime, an implementation that is not the obvious
   intended one. Do **not** yet judge how it is exploited; just flag it.
5. Be ready to say **which node has the broadest blast radius** — the bean with
   the most incoming injection edges.

There is no answer key in this folder. Produce your graph and annotations on
your own.
