CASE 3 — Credentialed request against a wildcard origin

Scenario
--------
The dashboard at https://dashboard.example.com calls
https://api.example.com/account with credentials: 'include', so the
browser attaches the user's session cookie to the cross-origin request.

Browser console
----------------
Access to fetch at 'https://api.example.com/account' from origin
'https://dashboard.example.com' has been blocked by CORS policy: The value
of the 'Access-Control-Allow-Origin' header in the response must not be
the wildcard '*' when the request's credentials mode is 'include'. The
credentials mode of requests initiated by the fetch() API can be
controlled by the 'credentials' option.

Network panel — Request
------------------------
GET /account HTTP/1.1
Host: api.example.com
Origin: https://dashboard.example.com
Cookie: session=abc123...
(request made with credentials: 'include')

Network panel — Response
--------------------------
HTTP/1.1 200 OK
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true
Content-Type: application/json

{"id":42,"name":"Ada Lovelace"}

(Access-Control-Allow-Origin is the wildcard '*', combined with
Access-Control-Allow-Credentials: true — the browser discards the
response before script ever sees it, even though the server responded
200 with a well-formed body.)
