# Web Development with JavaScript — Secure-by-Design (student code)

Code projects for the **student** side of *Web Development with JavaScript — Secure-by-Design* (Cyber Developer Associate, Phase 6 — Secure Web and Front-End Development). Secure client-side JavaScript: Content Security Policy, input sanitization, secure data fetching, and secure JSON parsing.

## Conventions
- **No build system, no frameworks, no external CDNs.** Vanilla HTML + ES2020 JavaScript. Open a project's `index.html`, or run the shared dev-server where a project's README says so.
- Layout: `modules/<NN-module>/lessons/<NN-lesson>/<activity>/starter_proj/`
- **Shared dev-server** `_server/serve.js` (zero dependency, Node's `http`): serves the project dir, applies response headers from an optional `headers.json` (used by Module 1 for real `Content-Security-Policy` delivery), exposes a `/csp-report` sink and a mock API (`/api/echo`, `/api/user`, `/api/hostile`, `/api/crash`) used by Module 3. Run from a project dir: `node ../../../../../../_server/serve.js` then open `http://localhost:8080`.
- **DOMPurify 3.4.12** is vendored locally in the Module 2 projects that use it (no CDN).

## Modules
1. Content Security Policy for Client-Side Apps (server-backed — real CSP response headers)
2. Robust Client-Side Input Sanitization (static; DOMPurify + manual encoders)
3. Secure Data Fetching and API Consumption (mock-API-backed; L12 is a fixture-only CORS diagnosis)
4. Secure JSON Parsing and Object Handling (owned RTI topic; L20 integrative graded lab)

Each project's `README.md` states **Your task / Files / Acceptance criteria**, verified in the browser DevTools console/network panel.
